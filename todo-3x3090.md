
**3×3090 configuration - as two engines, because one engine cannot span three cards for this model.**

**Why not TP=3 (the key constraint):** vLLM requires the KV head count to divide evenly across ranks (or TP to divide it for replication). This model's target has **4 KV heads** and the DFlash2 drafter **8** (`docs/long-context.md`), `drafter/README.md`- neither divides by 3, so TP=3 is rejected at startup. PP=3 is equally out: 64 layers don't split by 3. The only way to use all three cards is multiple engines.

**The layout now in the files:**

1. `docker-compose.yml`
   - `x-serve` anchor: `count: 2` → explicit `device_ids: ['0', '1']`, so `single`/`batch` always get the pair (deterministic, and leaves card 2 free)
   - New `solo` service: same single-user launcher, one card (`device_ids: ['2']`), own port from `SOLO_PORT` (18021), own healthcheck, and `EXTRA_ARGS: ""` overriding the `.env` file so the TP=2 flag doesn't leak into it


2. `.env`
   - `EXTRA_ARGS=--tensor-parallel-size 2`- the main engine (GPUs 0+1) keeps the measured +16–35% path (#40)
   - `SOLO_PORT=18021`- the third card's endpoint
   - `VLLM_OFFLOAD_KEEP_SHM=1`- **required with two serve containers**: both share the host `/dev/shm` (`ipc: host`) and each launcher's stale-region reaper (`single-user/start_qwen.sh`) can only see its own container's processes- without the flag, one engine's boot scan would delete the other's *live* offload region (#33; the flag is exactly the escape hatch its comment documents)

**On the GPU box (profile solo):**

```bash
nvidia-smi -L                  # confirm 3 cards
sudo nvidia-smi -pl 250        # per card
docker compose --profile single --profile solo up -d
docker compose logs -f single solo
```
fast endpoint at `:18020` (TP=2, DFlash2, ~161 tok/s C1 per #40) and a second independent endpoint at `:18021` (single card, ~127 tok/s)- e.g. two users, or one user + a background/agent workload on the spare card. `batch` remains exclusive with `single` (same cards). Note the two engines double model prep cost on first boot (each container downloads/requants ~20 G into its own `/cache` unless you set `MODELS_DIR` to a shared location).
